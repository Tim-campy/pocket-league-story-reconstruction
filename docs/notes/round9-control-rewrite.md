# Round 9 complete-control reconstruction proposals

The source AST emitter is independent of both original and recompiled CIL. This renderer consumes its complete tree and the original complete tree, authenticated bindings from existing source leaves to actual own CIL, and the frozen smcs slot model. It changes source text only. Complete candidates with wrong local signatures are rejected; neither a candidate CIL DTO nor compiler-generated classes are fabricated.

Reproduce the calculation with `python tools/round9_control_rewrite_calculate.py`. The input is the frozen post-B10 checkpoint under `build/round9/cycles/b10/after/Assembly-CSharp`; output is `reports/round9-control-rewrite-audit.json` and `reports/round9-control-rewrite-patches.json`. This is a NoEmit analysis operation and compiles no game assembly. External proposals use family `c9-control-skeleton`, exact UTF16 source spans and unique exact rebase of the original declaration. The adopter must repeat the model gate and run the full byte verifier. The candidate result remains UNKNOWN until that oracle runs.

The audit covers all 164 pending bodies: 132 have an incomplete original or source control IR; five lack mapped source; fourteen have identical complete control skeletons (five already have exact predicted local types and nine lack an approved generic Solver7 declaration edit); five have incomplete value-leaf binding; one otherwise bindable method has unanchored zero-IL declarations and is refused. Seven control proposals cover 2,165 original IL bytes. The independently frozen unused-suffix calculator adds DrawWindow2 (104 bytes), giving eight potential methods and 2,269 bytes. These are potential gains, not verified matches.

Source authentication checks the raw file SHA against both build manifest and own verification receipt. The binder checks every AST leaf text against its UTF16 span in that same frozen source and source-plan/tree equality against actual compiled own CIL. Each proposal records `source_text_sha256`, `source_file_sha256`, `own_body_source_bound`, `own_compilation_receipt_sha256`, original and own dump SHA, plus calculator/model/client/dependency hashes. Fingerprints preserve actual leaf instructions and operands; ambiguous repeated leaves and mismatching leaf counts are refused.

The renderer preserves source fragments in emission order. Sorting by textual position would incorrectly move a for iterator from after the body to before it. The new ForIteratorOrder fixture proves the corrected order with the historical smcs compiler. Declarations without initializers have no CIL leaf; Team.Update_coatEvaNewDeffence has cx, cy and passer in this category. Their lexical anchor is not proved by the current renderer, so that method is explicitly excluded rather than dropping or moving the declarations.

`tools/test_round9_control_rewrite.py` exercises five independently authored positive cases: integer polarity, float polarity with explicit negation and .un semantics, do/while reconstruction, for-iterator order, and calculated named-slot composition using real original and own DTOs. All five produce exact complete toy method bodies and local signatures. Seventeen toy assemblies were compiled; no game build was performed. Changed source payloads with identical control skeletons and unanchored zero-IL declarations are negative cases. The frozen independent root proof additionally checks rejected source-text/plan tampering, exact unused-suffix emission and reordered leaf binding.

The shared trace projection is copied unchanged with SHA256 82260d8007d9c2da95d9ae32c831fa3e6f340be1e85276fe41429c9d6921aed0. Unsupported EH ownership, generated caches, switch and ambiguous loop ownership remain incomplete; normalization never discards transfers or changes opcode widths.

Executable dependencies are listed only under `dependency_sha256` with `tools/` paths. Read-only `reports/` proofs are separate under `evidence_sha256`; their contents are never executed.
