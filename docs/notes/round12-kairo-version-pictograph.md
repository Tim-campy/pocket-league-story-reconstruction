## AddPictograph — local inside dictionary setter

Identity: `kairo.unity.ui.TextLayout::AddPictograph(String,Seb,Int32,Int32,Int32,Int32,Int32)->Pictograph`, token0600056c, original105 IL / current107 IL. Original REA decoded47/47, maxstack9, no EH. Original local signature is one Pictograph; current has two. The exact normal source change is `pictograph = (pictographList_[key] = new Pictograph(...));` to `pictographList_[key] = (pictograph = new Pictograph(...));`. The caller-bound symbol is the explicit local declaration, not a field/property. Setter/key/new-argument evaluation order is preserved; local assignment now happens before the setter as required by original IL. The original uses `dup; stloc.0; callvirt setter`; current spills an additional assignment-value temporary and reloads/stores it after the setter.

This is the known local-inner assignment mold, applied to this exact pending method, not a claim of a newly discovered generic primitive. Roslyn's assignment emitter (1717–1773,2122–2163,2245–2253) explains why an assignment result with a receiver/key on the stack needs a temporary, whereas the inner simple local store uses dup directly. Owned current/control/candidate prove whole-body equality of candidate and independently handwritten control; current differs. A split setter/re-read variant has the same local inventory but fails the whole-body control, demonstrating local count alone is insufficient. Semantic controls test absent/existing entries, wait clamp, same object identity, property updates, creation count and null-key exception.
